# AGENTS.md

## Session Bootstrap (Required)
Перед началом любой новой сессии в этом репозитории:
1. Прочитай `files/project-context.md`.
2. Учитывай зафиксированные там продуктовые договоренности, брендинг и историю принятых решений.
3. Если `files/project-context.md` отсутствует или устарел, сообщи об этом и предложи обновить.

## Context Priority
При конфликте источников приоритет такой:
1. Прямые указания пользователя в текущем диалоге.
2. `files/project-context.md`.
3. Остальной контекст репозитория.

## Persistence Policy
После крупных изменений обновляй `files/project-context.md`:
- что изменено,
- какие ограничения/договоренности появились,
- что осталось сделать.

Обновление делать автоматически командой:
`./scripts/update-project-context.sh`

В конце каждой завершенной рабочей сессии (перед финальным ответом пользователю) запускай этот скрипт.

## Token Efficiency Policy
Цель: минимизировать расход токенов на служебные операции и держать фокус на коде.

1. Сначала код, потом проверки:
- Не запускать промежуточные `compile/test` после каждого мелкого патча.
- Выполнять проверки один раз в конце серии изменений (или при явном риске поломки интерфейса/контракта).

2. Избегать широкого чтения:
- Не делать большие `sed/cat` по длинным файлам без необходимости.
- Читать только нужные фрагменты по `rg -n` + адресным диапазонам строк.

3. Сокращать дубли:
- Не повторять одни и те же поисковые/диагностические команды, если контекст уже получен.
- Не запускать одинаковые команды в параллели без необходимости.

4. Проверки по уровню риска:
- Для локальных UI-правок: ограничиться targeted-проверками и финальным `compile`.
- Полный `test` запускать в конце или по запросу пользователя.

5. Веб-поиск:
- Использовать только когда реально нужен внешний источник или меняющиеся данные.
- Не дублировать поиски по одной теме в рамках одной подзадачи.

6. Отчетность:
- В финальном ответе кратко указывать, какие проверки были выполнены и какие сознательно пропущены для экономии времени/токенов.

## Git Staging Policy
Если агент создает новые файлы в рамках задачи, их нужно автоматически добавлять в индекс git в этой же сессии:
- использовать `git add <path>` для каждого созданного файла,
- не откладывать staging до отдельного запроса пользователя.
